## 3. Four-audience fit (Sub-ask 2)

The template **already self-positions against these exact audiences** — by scoping
three of them *out* on purpose (`README.md:39`, `:761`). That sharpness is a strength,
not a gap. The Staff-level question is *on-ramps vs scope-creep*. Recommendation per
audience — **widen the on-ramp, never the identity**:

| Audience | Current posture | Recommended on-ramp (no identity dilution) |
| ---------- | ----------------- | -------------------------------------------- |
| **DS exploring / notebooks** | Out of scope (`:39`) | Ship a `notebooks/` quickstart that *consumes* `common_utils` (seed, persistence, Pandera schema) so a notebook user touches the contracts early, then "graduates" to the service. Keeps identity; lowers the cliff. |
| **Batch-only pipelines** | Out of scope (`:39`) | The training + DVC pipeline + quality gates are already batch. Add one ADR + a `batch/` Kustomize overlay running the existing container as a `CronJob`/`Job` instead of a Deployment. ~1 day; reuses 90%. |
| **Vertex AI / SageMaker teams** | Out of scope (`:39`) | Don't reimplement their orchestrators. Document an "export surface": the container, `model_card`, Pandera schema, and SLO rules are portable; show how to register the same image in Vertex Model Registry / SageMaker Model Package. Positioning doc, not code. |
| **LLM / GenAI** | Out of scope, routed to sibling `agent-local` (`:761`) + ADR-028 LLM-assist | Already the right call. Keep the wall: this template governs *classical* ML serving; the `agent-local` repo owns LLM serving. ADR-028 covers LLM-*assisted ops*, which is the correct seam. |

**Bottom line:** you do not need to "integrate" all four into one template — that path
ends as ZenML/Kubeflow (broad, heavy, identity-diffuse). You need **three thin
on-ramp docs/overlays** that let each audience touch your contracts without you
absorbing their platform.

## 5. "Empty contracts" critique — Memory Plane & CI Self-Healing (Sub-ask 4)

**Verdict: the critique is factually wrong as stated, but points at a real strategic
choice you should defend explicitly.**

These are **not empty** — they ship real, tested code, *honestly labeled* as Phase-1:

- **CI Self-Healing (ADR-019).** `README.md:370` is a model of disclosure: the
  classifier + collector ship today (`scripts/ci_classify_failure.py`,
  `ci_collect_context.py`), governed by `ci_autofix_policy.yaml` +
  `model_routing_policy.yaml`, with **10 policy-contract invariants + 27 Phase-1
  runtime invariants** in `test_ci_autofix_policy_contract.py` and
  `test_ci_classify_failure_phase1.py`. It runs in **shadow mode** (observes, emits
  classifications, writes nothing, opens no PRs). The patch worker is explicitly *not
  implemented*, gated on 14 days of shadow data per ADR-019.
- **Memory Plane (ADR-018).** Ships `memory_types.py` + `memory_redaction.py` +
  `test_memory_contracts.py` (and a `test_phase0_disclosure.py` that *enforces the
  honesty*). Types + redaction pipeline are real; ingest/vector/retrieval are deferred.

So: **contracts + types + tests + a wired shadow lane**, with a test whose job is to
fail if the docs over-claim. That is the *opposite* of vapor.

**The legitimate critique** is a posture question, not a correctness one: *should a
portfolio/enterprise template carry capabilities that are disclosed-but-inert?* Two
defensible answers:

1. **Keep as-is (recommended for the template).** Phase-gating with contract tests
   first is exactly how regulated orgs ship risky autonomy. The disclosure is
   exemplary. This demonstrates *judgment* — which is the portfolio signal.
2. **Promote one to runtime to prove the pattern end-to-end.** If you want a
   demo-able "wow", make **Memory Plane** real first (it's lower-risk than autonomous
   CI writes): wire ingest→redact→store→retrieve against a local store, behind the
   existing contracts. CI self-healing should stay shadow until you genuinely have 14
   days of signal — promoting autonomous-write CI early would *itself* be the anti-
   pattern.

**Interview framing:** "I ship the contract and the shadow lane first, with a test
that fails if my docs over-promise, and I gate write-access on observed evidence" is a
*stronger* Staff-level story than a flashy half-working autofixer. Defend it; don't
apologize for it.
